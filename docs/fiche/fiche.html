Workflow autonome
Fiche d'essai

Des agents libres de travailler, des modèles adaptés et un objectif suivi.

1. Un objectif, des issues

La campagne relie l'objectif final aux issues et à leur progression dans Linear. L'orchestrateur suit les dépendances et coordonne les agents. Les campagnes existantes gardent leurs travaux et leurs preuves.

2. Travail autonome

Le workflow aide à choisir un modèle proportionné : une modification simple ne nécessite pas un modèle très puissant. Les agents choisissent leurs méthodes, leurs outils, les tests et revues adaptés. Ils limitent les transferts de contexte inutiles.

Bonne conduite : respecter les règles du projet et les contrats existants ; préserver les routes d'API, les données, la sécurité et les comportements hors demande. Signaler les limites et ne pas déclarer un contrôle non effectué comme réussi.

3. Présentation locale

Les agents intègrent leurs travaux sur une branche de campagne et présentent une version locale, son SHA, les instructions d'essai et un court bilan.

Aucune fusion vers la branche principale avant ton test et ton GO explicite sur le SHA présenté. Si le candidat ou sa base change, l'agent te présente une nouvelle version.

Après ton GO

4. Fusion et suivi

L'agent vérifie la version et la base actualisée, puis fusionne la version validée. Il met à jour les issues Linear et consigne les acquis et décisions utiles dans Obsidian. Le déploiement reste distinct et sous les autorisations de chaque projet.

Ce qui reste garanti

  • Paul est l'unique autorité humaine ; les secrets ne figurent pas dans les preuves.
  • Aucun gestionnaire de mots de passe ; les suppressions passent par la Corbeille.
  • Le workflow n'impose ni matrice, ni double recette, ni revue à neuf systématique. Les critères de Paul et les règles du projet restent applicables.
  • Le pilote aide à enregistrer et vérifier le GO ; il ne peut pas intercepter un Git ou une interface externes.

Commandes de suivi

pilote.mjs contexte <campagne> : état et consignes.
pilote.mjs modele <tâche> <criticité> <volumétrie> : choix du modèle.
pilote.mjs validation-locale presenter|go|verifier <campagne> : présentation et vérification de la version ; détails dans le skill.
